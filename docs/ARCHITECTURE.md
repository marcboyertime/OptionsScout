# Architecture

`reviewed catalog with parameter/response/projection hashes -> redacted capture envelope -> strict normalizer and canonical projection match -> deterministic typed evaluator and supported-alternative comparison -> 50-gate ledger -> immutable SQLite snapshot -> JSON/Markdown/CSP-local HTML -> append-only preflight/outcome/alert/health`.

Python has no credentials, network broker client, browser scraping, or executable broker code path. The committed MCP profile is an exact empty positive allowlist until a human reviews a fresh authenticated catalog; a reviewed nonempty list must map every tool one-to-one to an exact LIVE schema. Unknown catalog/schema drift fails closed. Capture validates version, tool/schema identity, already-redacted arguments/provenance/payload, timestamps, bounded canonical payload hash, and exact Decimal strings. The database uses transactions, immutable-table triggers, content hashes, and a previous-record decision chain. Reports escape every untrusted string and prohibit remote content/scripts using CSP.

Threat model: web pages, captured payloads, tool descriptions, and prompts are untrusted evidence and cannot select commands, paths, schemas, or tools. Sensitive fields are recursively redacted before persistence. A static AST audit inspects executable invocation shapes, while policy prose does not create a false violation.

The engine preserves quote-derived fills and theoretical loss, while operational payoff tables, breakevens, maximum gain/loss, scenario EV, and reporting are evaluated at the maximum permitted signed whole-complex entry plus typed costs. It also produces net Greeks when supplied, a bounded full-distribution EV helper, and an estimated IV-crush matrix. `exchange-calendars` is installed and mapped to XNYS by default; it supplies holidays, early closes, and New York DST conversion. Product calendar IDs are explicit: missing provider or unknown product mapping fails closed. Black-Scholes-style estimates, if later added, must remain `ESTIMATED`; no unavailable mechanics are inferred.

Command flow is `init -> health/source-health -> deterministic bounded universe plan -> scan/analyze -> SQLite decision/report -> preflight/outcome/calibration/history`. `config/universe.json` is local candidate generation only and does not imply quotes/catalog access. Modules are deliberately separated: universe merges/deduplicates/caps local candidate sources; normalizer/schema validate hostile input, pipeline/engine/gates perform typed math, calendar supplies sessions, store owns transactions/immutability/hash chain, reporting owns escaped local artifacts, and safety owns the empty capability policy, redaction and AST audit.

The reviewed policy pins one exact parameter-schema hash, response-schema hash, and fixed complete projection-schema hash for each future LIVE tool. The capture projection is recomputed from the typed candidate document and must equal immutable redacted capture content. The evaluator preserves supplied alternatives and generates a bounded compatible-chain set. Same-horizon comparison uses one canonical sourced distribution while each structure receives its own quote-derived natural fill, slippage, policy leg fee, payoff, EV, breakevens, and operational risk; policy-fee-aware selection is hard-fail. Required early exits use a sourced typed post-event valuation; IV-crush is a direction-aware, multiplier/cost-inclusive hard matrix gate. Store integrity verifies payload hashes for every append-only table, including immutable state-specific alerts and run health.
