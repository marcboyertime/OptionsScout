# Scheduling

`options-scout schedule-plan --json` creates a root-bound orchestration prompt, one disabled shell, a disabled deep/weekend launchd template, and a separate disabled 15-minute launchd template. The deep template has weekday 05:30 and 16:30 calendar triggers plus Saturday 10:00; the 15-minute template invokes a local exchange-calendar gate that exits without a runner outside XNYS regular hours or before open plus 15 minutes. No automatic five-minute job is created; that cadence is reserved for a previously qualified active candidate after a future complete rerun. The shell uses the deployed absolute `.venv/bin/options-scout`, exports the fixed root, changes to that root, acquires a mkdir non-overlap lock for a due run, and applies a 20-minute subprocess timeout. `--test` executes only `source-health --json`: it validates either the default exact `EMPTY_AND_FAIL_CLOSED` / `DATA_INSUFFICIENT` state or a reviewed-ready policy/profile match, and never scans, invokes a runner, or mutates. Templates are neither installed nor activated and contain no broker operation. Deploy the console with the documented non-editable `.venv/bin/python -m pip install '.[dev]'` install so the absolute launcher contains copied package code on Python 3.14/macOS.

The disabled `--run` path is a guarded future Codex orchestration entry, not a broker client. It refuses unless `config/policy.json` has a nonempty one-to-one reviewed LIVE schema allowlist, `.codex/config.toml` enables the official Robinhood server with the exact same tool list, and `source-health` reports `REVIEWED_READ_ONLY_CAPTURE_POLICY_READY`. It also requires `OPTIONS_SCOUT_CODEX_RUNNER` to name one absolute executable file. That runner receives one root-bound prompt requiring exact allowlisted read-only catalog use, an already-redacted capture, `capture-ingest`, a cryptographically bound typed input, and only then `scan --input`; application gates independently reject missing, altered, stale, or mismatched captures.

Suggested cadence after live latency/rate-limit measurement: deep premarket, regular-session refresh about 15 minutes after open, deep after-close, weekend catalyst refresh, and five-minute refresh only for an already active candidate. Activation remains forbidden in the current state. After unattended OAuth and the exact catalog/schema/runner behavior have been demonstrated, a human must update both allowlists identically, set the absolute reviewed runner in the scheduler environment, rerun `--test` and a controlled `--run`, and inspect the resulting capture, decision, report, and safety audit.

The reviewed policy must pin the exact parameter, response, and fixed complete normalized-projection schema hashes for each read-only tool before `--run` can ever be considered. A reviewed-ready `--test` validates that policy/profile state without runner invocation; default empty policy still validates only the fail-closed branch. The runner prompt requires capture ingestion before a bound scan, and that binding verifies the immutable redacted projection rather than trusting a declared hash.

Only after those prerequisites pass, activation is: copy each desired plist into `~/Library/LaunchAgents/` using filenames matching its `Label`; remove the copied plist's `Disabled` key with `/usr/libexec/PlistBuddy -c 'Delete :Disabled' FILE`; set the absolute runner with `launchctl setenv OPTIONS_SCOUT_CODEX_RUNNER /ABSOLUTE/REVIEWED/RUNNER`; then load each selected job with `launchctl bootstrap gui/$(id -u) FILE`. Confirm it with `launchctl print gui/$(id -u)/LABEL` and immediately inspect `options-scout history --limit 1 --json` plus `options-scout safety-audit --json`. Rollback is `launchctl bootout gui/$(id -u) FILE`, `launchctl unsetenv OPTIONS_SCOUT_CODEX_RUNNER`, and restoration of both profiles to empty/disabled; retain the generated test artifact and run `source-health` to confirm fail-closed state.
