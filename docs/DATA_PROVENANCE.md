# Data provenance

Reviewed LIVE capture records pin three canonical SHA-256 schemas: parameter, response, and a fixed complete normalized-projection schema. The projection is not a policy-supplied free-form list: ingest enforces its exact nested object fields, including run metadata/source plus each candidate's underlying, quote provenance, mechanics, and each contract's identity, mechanics, and quote fields. It retains only schema-bounded public candidate and option-contract IDs; account, user, order, position, and opaque authenticated objects are rejected. Operational binding recomputes that projection from the typed document and requires exact equality with the immutable redacted capture payload, in addition to exact tool/schema/hash/timestamp and whole-document normalized-input-hash checks. Thus an envelope-declared hash cannot authorize unrelated quote or mechanics data.

Each capture uses a strict version-1 envelope with `tool`, `schema_identity`, `redacted_arguments`, capture ID, `as_of`, retrieval timestamp, field provenance, source label, bounded redacted payload, and SHA-256 payload hash. The default empty policy rejects broker envelopes. After human review, `capture-ingest` can append only an already-redacted envelope whose tool/schema/LIVE source exactly match a strict positive policy; it runs no broker tool. Unredacted sensitive payload, arguments, or provenance are rejected rather than silently transformed. Fixtures use the separate `options-scout.fixture.v1` namespace and are permanently non-live. Valid labels are `LIVE`, `DELAYED`, `CACHED`, `HISTORICAL`, `ESTIMATED`, and `UNAVAILABLE`.

External text is untrusted evidence only. Research claims retain title, publisher, URL, publication/event/retrieval dates, primary/secondary inference label, and thesis-claim mapping. Sensitive keys are redacted before persistence. Decimal money arrives and serializes as strings; binary float money is prohibited. Decision reports also identify input/config/model versions, source timestamps and labels, normalized-input hash, and Git revision when supplied. Capture, source, research, decision, IV, structure-trace, and gate snapshots are immutable; preflights and outcomes are separate append-only records.

Operational CLI input needs a strict capture binding: immutable capture ID, approved tool/schema/source identity, capture-payload hash, canonical normalized-input hash, and capture timestamps must match exactly. The normalized-input hash covers the complete normalized document except the binding itself, preventing a capture from being reused with altered quotes, thesis, or economics. Candidate quote provenance source must exactly match the run source. Contract and mechanics exercise labels are exactly `American` or `European`; settlement labels are exactly lowercase `physical` or `cash`. Aliases, spaces, and casing variants are rejected before evaluation. Typed prices are nonnegative, strikes/underlying and supplied IVs are positive, Greeks use bounded/sign-consistent domains, and supplied mark must lie inside an uncrossed bid/ask. Metadata, underlying, and every option quote timestamp must equal the captured timestamp and pass wall-clock freshness. A self-declared `LIVE` JSON file is only a snapshot. The default Phase 1 approved capture list is empty, so all non-fixture CLI input remains `DATA_INSUFFICIENT`; a nonempty policy is valid only after exact human schema review and a matching `capture-ingest`. Fixtures remain explicitly non-live. Pure snapshot evaluation is test/research-only, never an operational LIVE authorization.

Typed portfolio positions and correlations exist only in memory while risk and duplicate-expression gates run. Duplicate expression is computed from the proposed symbol/factor context plus same-symbol or high-correlation overlapping-factor records; a nonempty unrelated portfolio is not a duplicate. `portfolio-check` returns `DATA_INSUFFICIENT` when that proposed context is absent rather than treating positions as a proxy. Position IDs, symbols, sectors, factor tags, correlation prose, and deficit-rationale prose are replaced before evaluation serialization by limits, aggregate risks, counts, and gate-relevant booleans; gate evidence also contains counts rather than position identifiers. The same sanitized evaluation is the only form passed to reports, history, alerts, preflight, and SQLite decision tables. `portfolio-check` does not echo or persist its typed position/correlation input.

The SQLite store contains `captures`, `sources`, `research`, `candidates`, `iv_snapshots`, `structure_traces`, `gate_results`, `decisions`, `preflights`, `outcomes`, `alerts`, and `run_health`. Decision records chain a canonical SHA-256 hash to the previous record. Immutable snapshot tables reject UPDATE/DELETE with SQLite triggers; migrations are transactional. `health` and `safety-audit` run SQLite integrity plus chain verification, so a bad chain is evidence to preserve, not a record to repair.

Every append-only payload class also carries a verified payload SHA-256, including alerts and run-health records. Alerts are state-specific immutable events rather than updates. Migrations backfill legacy payload hashes across captures, sources, research, candidates, IV snapshots, structure traces, gate results, outcomes, preflights, alerts, and run health before their update/delete triggers are installed; a hash mismatch is retained as tamper evidence.
