# Phase 1 safety audit

1. `AGENTS.md`, the repository skill, policy config, runtime assertion, schedule plan, and static AST audit all state/enforce research-only behavior. A deliberate executable forbidden-call fixture is tested and fails the audit.
2. The committed/default broker profile is an exactly empty positive allowlist; unknown tools/schema drift fail closed. A future nonempty profile is accepted only when every unique enabled read-only tool has one exact reviewed LIVE schema record and no forbidden capability substring. The application has no broker HTTP or execution code. The repository `.codex` profile is disabled with `enabled_tools=[]`.
3. Raw sensitive data is bounded and redacted. Typed portfolio records are transient: adversarial tests prove position IDs, symbols, sectors, factor tags, correlation prose, and deficit-rationale prose do not enter evaluation payloads, reports, CLI portfolio output, history, alerts, preflights, or any SQLite decision table. Only risk limits, aggregate risk values, record counts, and gate-relevant booleans survive serialization.
4. SQLite capture, decision, source/research, IV, structure trace, and gate snapshots have update/delete triggers where immutable and a SHA-256 previous-record decision chain. Outcomes and preflights are separate append-only records.
5. Fixture mode is permanently non-live and blocked from `ACTIONABLE`. CLI LIVE claims must bind the canonical normalized input as well as the capture payload to an immutable capture record and reviewed tool/schema/source/hash/timestamp identity; altered input and stale/future metadata fail closed. `capture-ingest` only validates/appends an already-redacted reviewed envelope and never calls a broker. The default empty allowlist prevents operational ACTIONABLE output.
6. Universal intended loss is <=$1,000 inclusive of premium, defined settlement, fees, commissions, planned entry/exit slippage, and the declared maximum acceptable whole-complex fill. Costs and portfolio risk/limits cannot be negative; scenario payoff and EV are derived/verified from typed bounded expiration spots and maximum-permitted whole-complex cash economics. Operational mechanics must eliminate assignment, physical equity exposure, and deficit risk. Any short requires a verified index with all legs European cash-settled; physical options cannot be held through expiration.
7. Upcoming binary events require dated typed IV-drop provenance and complete Greeks. Preflight binds the selected topology/order and every ordered leg's immutable contract/economic/mechanics term before retaining ordinary quote/Greek/IV refresh differences. It invalidates identity drift, stale/crossed/missing data, a rerun hard-gate failure, >2% underlying move, mechanics/portfolio/thesis/source change, or worse economics.
8. The static scan distinguishes declarative denial text from executable invocation sites. Generated schedules are disabled/test-safe, absolute-path based, locked, timed out, source-health checked, and contain no mutation path. `--run` refuses before both the strict policy and repository Codex profile contain the same nonempty reviewed allowlist; it then invokes one explicit absolute executable with one root-bound orchestration prompt. Tests prove the default policy cannot reach that runner.
9. Future LIVE capture review pins exact parameter, response, and complete canonical projection-schema SHA-256 values. Operational binding recomputes the quote/mechanics projection from typed input and requires exact immutable-capture equality, so an envelope-supplied normalized hash cannot authorize unrelated payload. Supplied and bounded generated alternatives share a canonical sourced distribution but derive independent natural fills/costs/payoffs; policy-fee-aware selection fails closed. Required early exits use typed post-event valuation; direction-aware all-cost IV-crush failures block actionability.
10. Every append-only payload class is immutable and hash-verified: captures, research, outcomes, preflights, state-specific alerts, and run health. Tampering that bypasses a SQLite trigger is detected by child-hash integrity verification; legacy rows receive hashes before triggers become active.

Known fail-closed limitation: no human-reviewed authenticated read-only schema and matching fresh redacted market-data capture were exposed in this task. This is the only external Phase 1 blocker. Robinhood's [official overview](https://robinhood.com/us/en/support/articles/agentic-trading-overview/) documents the broad account access and possible trading authority, supporting the conservative default profile. Therefore operational scans return `DATA_INSUFFICIENT` rather than simulating a live recommendation.

Calendar evidence is different: `exchange-calendars` is a local installed dependency and `calendar.py` maps XNYS. Availability, unknown calendar ID, holiday, early close, and time-zone classification are all reported locally; this does not prove a broker's product mechanics mapping.
